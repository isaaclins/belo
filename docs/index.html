Teach your machine to see.

Belo trains an image classifier on your own pictures, on your own machine. No account, no upload, no network calls.

Get Belo See how it works
  • 0network calls at runtime. The MobileNet weights ship inside the app.
  • 224pixels square. Every image is center cropped and normalized on import.
  • 7×7feature cells behind the attention overlay, roughly 32 pixels each.
  • MITlicensed, and the .belo bundle is a folder you can open.

Three tabs.
One loop.

Label your pictures, train a head in seconds, then point a camera at the world. Every correction you make in the Use view goes back into the dataset and quietly retrains.

  1. 01

    Label

    Drag in single files or whole folders, import from disk, or hold the capture button for a webcam burst. Selections move between labels, four cell sizes change how many fit per row, and portrait frames are letterboxed rather than cropped.

  2. 02

    Train

    One click trains the dense head and reports live progress, training accuracy, a holdout score and a score per label. Every image is scored afterwards, so the ones the model still reads wrong are sitting right there, one click from being fixed.

  3. 03

    Use

    Point the webcam at something and watch the live call and its confidence, or drop in one image for a single verdict. Confirm or correct it and that frame joins the dataset, with a debounced retrain about four seconds after your last tap.

Live camera

Attention, not detection.

Turn the overlay on and Belo paints where the evidence for the current call sits: a tinted heat map plus one box per label.

It reads the classifier's own 7 by 7 feature grid, so it is a coarse hint at roughly 32 pixel resolution. It is never an object detector, and Belo does not pretend otherwise. The toggle starts off and is remembered until the app closes, never inside the project.

  • A camera picker appears as soon as the machine exposes more than one video input, and swaps the stream in place.
  • Phones hand out device ids that go stale, so a refused id retries on facing mode. Front and back switching stays reliable.
  • The live camera keeps classifying with the current model while a background retrain runs.

Two output shapes, picked once

The mode is chosen when the project is created and shown in the project header. Single label runs a softmax and reports one winner with a confidence. Multi label runs one sigmoid per label with a fixed 0.5 threshold, so a picture can be one thing and another thing but not a third.

Mock values. Images with no labels are ignored by training in both modes.

Hold to teach

Tap a teach button and Belo learns one frame. Hold it and frames keep coming until you let go, counting up on the button, capped at 60 per hold. Try it.

The rate control picks 2, 4, 8 or 12 frames per second and drives the Label view burst too, so the app has one capture speed. Frames are dropped rather than queued if the disk cannot keep up.

A frozen trunk and a small head

Trunk

MobileNet v1, 1.0, 224

Truncated at conv_pw_13_relu and spatially averaged into a 1024 value embedding per image. The weights are bundled with the app, so nothing is fetched. The same pass hands back the 7x7x1024 activation the overlay scores cell by cell.

Head

Dense, 100 hidden units, Adam

Only this part learns, which is why a run takes seconds instead of hours. Softmax in single label projects, one sigmoid per label in multi label projects, serialized to model/head.json when the run finishes.

Runtime

TensorFlow.js, WebGL then WASM

WebGL is picked first and WASM is the fallback when it is unavailable. The WASM binaries are copied in at build time. There is no inference server, no API key and nothing to sign up for.

Safety net

One checkpoint, one undo

Before each automatic retrain the current head is copied to head.prev.json. Revert to previous model puts it back. Manual runs write no checkpoint, so the action always means undo what the app did on its own.

A project is a folder you can open

Every project is a directory bundle named Project.belo. It behaves the same on macOS, Windows and Linux, and normal tools can inspect, diff and back it up.

Saves are incremental: only the manifest is rewritten on an edit, and it goes to a temp file and gets renamed, so a crash cannot leave you with half a file. Model export is out of scope for this version.

  • project.json carries the labels, the image records, the training settings and the model metadata.
  • Deleting a project asks first and names what goes with it. The Rust side refuses to delete anything that is not a .belo directory holding a project.json.
  • On iOS the bundles live in the app's sandboxed Documents folder, so they move between devices through a container backup for now.

Get it

Two ways in, both honest about where they are.

Desktop, built from source

There are no signed installers yet, so the real path today is to clone the repo and build it yourself. You need Node 20 or newer, Rust 1.77 or newer, and the Tauri 2 system dependencies for your platform.

git clone https://github.com/isaaclins/belo.git
cd belo
npm install
npm run tauri build
  • macOS
  • Windows
  • Linux

Windows runs through WebView2, Linux through WebKitGTK, where camera support depends on the installed build and is the least tested of the three.

Open the repo on GitHub

iPhone and iPad

App Store Coming soon, pending Apple review

The iOS build exists and runs: sandboxed project bundles, the native photo picker, bottom stage tabs and 44 point touch targets. The developer license approval is in progress, so there is no listing to link yet.

Minimum iOS 15.0. The simulator has no camera, so Belo shows a clear message there and takes photo import as the test path instead. Android is code complete but has not been built on an Android toolchain yet.
